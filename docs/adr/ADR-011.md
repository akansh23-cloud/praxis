# ADR-011 — Defer the external Phase 3 measurement while continuing deterministic Phase 4 development

## Status

Accepted, 2026-09-13. A governance decision, not a design one: it changes
one process rule in `AGENTS.md` and rule 4 of `docs/00-MASTER-PLAN.md`
(the same commit), and it is recorded against the FR-P3-07 row and the
Phase 3 slip note in `docs/PROGRESS.md`. It touches no code, no test, no
benchmark number and no tag.

## Context

Phase 3 has one exit requirement left. FR-P3-07 — `praxisbench run
--agent llm` measured over ≥5 runs × 6 scenarios, with the numbers in the
README — needs a real model provider, and the verification host has no
`ANTHROPIC_API_KEY`, no `ANTHROPIC_AUTH_TOKEN`, no `ant` profile and no
reachable Ollama. Everything else the phase asked for is implemented,
tested and pushed: the evidence pipeline and its redaction, the LLM agent
behind the seam, the CRD-derived planner, the citation validator, the
permanent prompt-injection pack, the same-commit rule-based comparison,
and the hardening. The scripted-endpoint proof of Session 3.3 shows the
path works end to end and is not a measurement; nothing has been
substituted for the missing campaign.

Two authoritative rules say the project must wait: `AGENTS.md` ("Do not
start the next phase's work early, even if it seems easy") and master
plan rule 4 ("Never advance a phase before its Exit criteria all pass.
The criteria are the contract"). Both were written to stop a very
specific failure — a phase declared done on partial evidence, and the
next phase built on the gap. They were not written for a criterion whose
only missing input is a credential the project cannot manufacture, and
whose result no line of the next phase depends on.

The maintainer decided on 2026-09-13 to continue with Phase 4 while the
measurement waits. `docs/PROGRESS.md` records that decision, but a
ledger note does not override the two rules above. This ADR is the
narrow, written exception those rules require — and the definition of
how narrow it is.

## Decision

1. **FR-P3-07 remains NOT MET.** Its row in `docs/PROGRESS.md` stays
   "deferred — not met" with its closure checklist unchanged.
2. **Phase 3 is not formally released.** Its status is *implementation
   complete / real-provider measurement deferred*, and every public
   document says so.
3. **`v0.1.0` remains prohibited** until FR-P3-07 closes. No substitute
   tag is created; `v0.1.0-alpha.1` is not moved.
4. **No real LLM benchmark result may be claimed** until the campaign has
   actually run against a real provider. Scripted or fake-provider runs
   are integration proofs and are never reported as model numbers.
5. **Phase 4 may proceed**, starting with Session 4.1 — the deterministic
   risk scorer and the policy gate — because that work consumes a
   persisted `RemediationPlan` and cluster state, is deterministic by
   design ("if you want the LLM, stop"), and does not depend on the
   numeric result of the deferred campaign. Nothing in Phase 4 may cite,
   assume or wait on those numbers.
6. **This is a narrow sequencing exception**, not permission to defer
   arbitrary future exit criteria. It applies to a criterion that depends
   on an external input the project cannot supply itself, is approved by
   the maintainer explicitly, and is recorded as an ADR plus a ledger
   checklist — all four conditions, every time.
7. **Never deferrable this way:** security invariants, admission and CEL
   rules, benchmark integrity (answer keys, the frozen baseline, the
   scorer, the agents' blindness to ground truth), the analyzer/executor
   architecture and its import boundary, and any criterion whose evidence
   the project can produce on its own. Engineering quality is never the
   thing deferred.
8. **The deferred item stays tracked** in `docs/PROGRESS.md` with its
   existing closure checklist: real-provider smoke, the full campaign with
   both telemetry seams on one named commit, the injection pack with a
   real model 5/5, the measured metrics (top-1, top-3, plan/schema
   validity, citation-rejection rate, restraint, time-to-plan, tokens,
   USD) with the exact model id and pricing basis, the README and
   `bench/RESULTS.md` update, then the release gate.
9. **When a credential is available**, the real-provider smoke and the
   full campaign must be completed and published before `v0.1.0`, on
   whatever commit is then current, with the rule-based comparison rerun
   on that same commit if the harness or the packs changed in between.

The corresponding wording changes: the `AGENTS.md` rule keeps its first
sentence and gains the four conditions and the tag-stays-blocked clause;
master plan rule 4 keeps "all exit criteria pass before advancing" as the
norm and names this controlled exception. The playbook's canonical copy
of the `AGENTS.md` block carries the same bullet so the two never
disagree.

## Consequences

**What this buys.** Deterministic Phase 4 work proceeds on a pushed,
CI-green Phase 3 without pretending the phase is released; the missing
measurement is a named, checklisted blocker on one artifact — the tag —
rather than an unwritten understanding; and the rule that stops phases
from advancing on partial evidence survives with its teeth, because the
exception is bounded by conditions this ADR spells out.

**What it costs.** The public v0.1 milestone slips by however long the
credential takes, and the README meanwhile carries a measured table with
an honest "deferred" row instead of the model numbers the master plan
wanted at week 10. If Phase 4 changes the harness or the packs before
the campaign runs, the rule-based side-by-side must be rerun on the
measured commit (decision 9), which costs one more campaign.

**Accepted trade-off.** Sequencing over ceremony, but only where the
missing evidence is external, the next phase is independent of it, and
the gate it guards stays shut.
