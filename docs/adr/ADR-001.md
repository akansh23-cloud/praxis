# ADR-001 — Closed action vocabulary

## Status

Accepted. Recorded in code as the `ActionType` enum in `api/v1alpha1/remediationplan_types.go`;
indexed in `docs/01-HLD.md` §10.

## Context

Praxis exists because an LLM can diagnose a Kubernetes incident well and cannot be
trusted to act on one. The whole design rests on a single boundary: the model that
reasons has no credentials, and the process that acts has no model.

That boundary is only real if the set of things the acting process *can* be asked to
do is finite and known in advance. If a plan could carry a free-form command, a shell
snippet, a raw patch, or an arbitrary `kubectl` verb, then every guarantee downstream —
blast-radius scoring, policy evaluation, dry-run simulation, snapshotting, rollback —
would have to reason about an open-ended input. Blast radius cannot be computed for an
action whose effects are not enumerable. Rollback cannot be written for an action whose
inverse is unknown. And prompt injection reaching the analyzer through telemetry (trust
boundary B1 in the HLD) would only need to smuggle a string past a filter to reach the
cluster.

The alternative considered was an open or extensible action surface — free-form patches,
a plugin-registered verb set, or "any verb the executor's RBAC happens to allow" — with
safety enforced by validation rules layered on top. That approach makes the security
argument a claim about the completeness of a filter, which is a claim that cannot be
checked.

## Decision

The action surface is a **closed vocabulary**, encoded as a `+kubebuilder:validation:Enum`
on the `ActionType` type and therefore enforced by the API server's schema validation:

    RestartWorkload · ScaleWorkload · RollbackRelease · PatchResourceLimits · CordonNode

Each verb carries its own typed parameter block, and `Action` is a discriminated union
whose CEL rules make the wrong combination impossible to persist rather than merely
flagged after the fact. Targets are single, fully-enumerated object references —
`TargetRef` deliberately supports neither wildcards nor label selectors, because a plan
that cannot enumerate its targets cannot have its blast radius computed.

The vocabulary is extended **only when a benchmark scenario demands it**, and each new
verb arrives with its risk-score base value, its reversibility classification, and its
`ActionExecutor` implementation (`Precheck`/`Snapshot`/`Apply`/`Revert`) in the same
change. There is no dynamic registration path and no escape hatch verb.

## Consequences

**What this buys.** Prompt injection cannot invent a verb: text that reaches the planner
through attacker-influenced telemetry can at most select badly from a list that is already
known to be survivable, and the selection is then scored, policy-checked, dry-run and
(at L2) human-approved. Rejection happens at the API server, before the object exists —
the earliest possible point, and one that does not depend on any Praxis code being
correct. Every downstream component gets an exhaustive `switch`: the risk scorer has a
base value per verb, the executor has one `ActionExecutor` per verb, and the compiler
catches an unhandled case when the vocabulary grows.

**What this costs.** Praxis cannot remediate anything outside the five verbs, and it will
sometimes be visibly unable to perform a fix a human would consider obvious. Adding a verb
is deliberately more expensive than adding a prompt instruction — it touches the API type,
the CRD, the scorer table, the executor registry, and the rollback path, and it requires a
new API version if the change is not additive. Extension pressure is therefore routed
through the benchmark rather than through user requests, which slows the project's response
to genuine gaps.

**Accepted trade-off.** Security over flexibility. A tool that fixes fewer incidents but
cannot be talked into an arbitrary cluster mutation is the product; the inverse is not.

**Related.** [ADR-004](ADR-004.md) applies the same reasoning to verification predicates,
which are still free-form in v1alpha1 and therefore the current exception to this
principle. Future vocabulary growth is pre-registered in `docs/01-HLD.md` §10 —
ADR-006 anticipates a `RevertGitCommit` verb for GitOps mode.
